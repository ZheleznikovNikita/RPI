# Игровое взаимодействие

## Сценарий пользователя

1. В меню гость выбирает «Начать игру», вводит команду и получает сообщение об отключённой нейросети. Вход не обязателен для знакомства с интерфейсом; гостевые команды не сохраняются.
2. После регистрации или входа «Начать игру» создаёт прохождение с инвентарём. Для существующей сессии меню показывает «Продолжить игру» и «Новая игра». Новая игра сначала открывает экран подтверждения замены незавершённого прохождения; завершённые игры сохраняются.
3. На игровом экране кнопка и Enter отправляют POST /game. Пустой ввод, одни пробелы, нестроковые параметры и команды длиннее 2000 символов отклоняются. Без JavaScript работает обычная форма с переходом обратно на GET /game.
4. Заголовок сцены и прежняя история остаются на месте; команда и новый ответ добавляются ниже. Пока ожидается ответ или печатается текст, повторная отправка блокируется. «Показать сразу» завершает печать. В настройках её можно отключить; системная настройка уменьшения анимации также учитывается. Ошибка сети сохраняет введённый текст для повторной отправки и показывается отдельно от продолжений истории.
5. Иконка рюкзака открывает инвентарь с предметами текущего прохождения, количеством и описанием; пустое состояние объясняет отсутствие предметов. Диалог закрывается крестиком, Escape и нажатием за его пределами. Кнопка с тремя полосками открывает плавающее меню профиля, главного меню, настроек и завершения игры; Escape или нажатие вне меню закрывают его. На ПК рюкзак расположен слева от меню, на телефоне — под ним справа от индикаторов.
6. «Настройки» позволяют менять громкость и режим печати, слушать музыку. Стрелка возвращает туда, откуда открыта страница. Значения сохраняются автоматически в localStorage этого браузера и действуют также в UI Kit.
7. «Профиль» позволяет войти, зарегистрироваться, изменить имя, открыть UI Kit и статистику. Возврат сохраняет контекст игры. «В меню» сохраняет активное прохождение; «Завершить игру» сначала открывает модальное окно подтверждения. «Продолжить игру», Escape и нажатие вне окна отменяют завершение. Подтверждение завершает прохождение и открывает статистику. После завершения стрелка из статистики ведёт в меню; при самостоятельном входе через профиль — назад в профиль.

Игровая страница занимает видимую высоту браузера без минимального размера 720 px. На маленьком экране уменьшаются отступы и шрифт истории, ввод и отправка остаются в одной строке. Прокручивается история внутри панели; сцена получает оставшееся место. Подсказка о сохранении прогресса скрывается после первой успешной команды, в том числе при возврате к сохранённому прохождению. Сообщения об ошибках и ожидании ответа продолжают показываться.

## Поведение без ИИ

`Storytelling::OfflineProvider` возвращает сообщение об отсутствии подключения как демонстрационное продолжение сюжета. Для аккаунта `Narrator` сохраняет запрос со статусом succeeded, действие completed, StoryTurn и версию StorySummary. Провайдер помечен offline, модель — demo; это заглушка без сетевого вызова. Демонстрационные действия учитываются в статистике. Если память ещё пуста, используется краткая отметка демонстрационного режима; существующая память сохраняется. При подключении настоящего адаптера это поведение заменяется его ответами.

Сессия, характеристики, инвентарь, отправленные команды и вся принятая история сохраняются в БД аккаунта. Неотправленный черновик временно хранится в sessionStorage этой вкладки отдельно для каждого аккаунта и прохождения. Он одинаково восстанавливается при возврате через браузер и через кнопки сайта; после успешной отправки очищается. После возврата заголовок сцены и сохранённые продолжения восстанавливаются; отправленные промпты не теряются. У гостя история существует только на текущем экране и при уходе или перезагрузке исчезает, но черновик также можно восстановить в этой вкладке. Настройки музыки, громкости и оформления хранятся в браузере независимо от входа.

Сообщение «Не удалось связаться с сервером» показывается только при сбое запроса или таймауте. Ответ HTTP 500 или некорректный формат ответа показываются как ошибка сервера отдельно от продолжения сюжета. Если новый каталог app/services появился после запуска Rails, требуется один перезапуск процесса; иначе старый загрузчик не найдёт Storytelling. Внешний API для демонстрационного ответа не нужен.

Сервер проверяет владельца через авторизацию, а не через переданный user_id. Идентификатор прохождения в форме используется только для обнаружения устаревшей вкладки. Если пользователь начал другую игру или вышел из аккаунта, старая вкладка получает понятный ответ 409. Запрос при уже обрабатываемом действии тоже получает 409 вместо страницы исключения.

## Подключение API рассказчика

Адаптер должен реализовать:

```ruby
def name
  "provider-name"
end

def model_identifier
  "model-name"
end

def call(payload:)
  # Выполнить HTTP-запрос к выбранному API и разобрать JSON.
  # Вернуть Hash со строковыми ключами:
  { "narration" => "Продолжение истории", "summary" => "Актуальная память сюжета" }
end
```

`payload` содержит `command`, актуальную `summary` и до 10 последних принятых пар command/narration в `history`. Оба поля ответа обязательны: непустые строки до 20 000 символов. Дополнительные поля сохраняются в сыром response_payload; характеристики и инвентарь автоматически из них не меняются.

Новый адаптер размещается в app/services/storytelling. Для его установки замените настройку в config/initializers/storytelling.rb, например:

```ruby
Rails.application.config.to_prepare do
  Rails.configuration.x.narration_provider = Storytelling::MyProvider.new
end
```

Перезапустите сервер. Вынесите ключ в переменную окружения или Rails credentials и читайте его внутри адаптера. Ключи и заголовки авторизации не должны попадать в payload, HTML или JavaScript. Адаптер должен быть безопасен для одновременного использования разными запросами и задавать короткие таймауты HTTP (например, подключение 3 секунды, чтение 10 секунд); браузер ожидает ответ до 20 секунд. Настройка адаптера сама по себе не включает вызовы для гостей.

Сетевой вызов происходит после создания AiRequest и вне блокировок БД. Корректный ответ сохраняется через succeed! и атомарный complete!. Исключение или неверный контракт завершают попытку ошибкой и разрешают новый ввод. Необработанный текст ошибки провайдера пользователю не показывается.

Генерация изображения потребует отдельного адаптера и обработки purpose=image: соответствующая модель и JSON-контракт уже есть, но сетевой клиент и отображение сгенерированной сцены в этой версии не подключены.

## Музыка

`app/assets/javascripts/music.js` синтезирует оригинальную спокойную композицию через Web Audio API: четыре мягких аккорда и мелодическая линия, повторяющиеся по кругу. Сторонние записи, семплы, загрузки, CDN и ключи не используются. Композиция и генерируемое аудио предоставляются на условиях CC0-1.0; атрибуция не требуется.

Музыка включена по умолчанию. Кнопка включения/выключения находится в настройках сразу под слайдером; её демонстрирует также UI Kit. Выбор сохраняется независимо от громкости: включение музыки не меняет установленные 0%. Игровой экран пытается запустить музыку автоматически; если браузер требует пользовательское действие, звук начинается после первого клика или нажатия клавиши. При сохранённом выключении музыка не запускается. В скрытой вкладке она приостанавливается, при уходе со страницы звуковой контекст закрывается. Блокировка localStorage не ломает текущие настройки, но не позволяет сохранить их после перезагрузки.

## Проверка

Автотесты в test/integration/game_interactions_test.rb покрывают гостевую HTML/JSON-отправку, валидацию, начало и завершение прохождения, повторы, инвентарь, подтверждение новой игры и устаревшие вкладки. test/services/storytelling/narrator_test.rb проверяет отключённый адаптер, успешный контракт, передачу памяти, ошибки и восстановление без настоящих сетевых запросов.

При ручной проверке дополнительно проверьте Enter, быстрые повторы ввода, постепенную печать и пропуск, музыку и 0% громкости, сохранение настроек после обновления, возврат в игру и ошибки сети с повторной отправкой. Проверьте это в узком и широком окне; генерация реальной истории и картинок требует подключения внешнего адаптера.
