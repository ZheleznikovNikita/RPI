# Адаптивная музыка RPI

## Как устроено

DeepSeek в существующем запросе рассказчика возвращает `music_mood` вместе с текстом, памятью, признаками физического усилия и изменениями HP/STA. Нового запроса, музыкального API и оплаты за генерацию аудио нет. Во входе передаются прежняя атмосфера, память и история: разговор во время боя не должен автоматически означать спокойствие.

```json
{
  "possible": true,
  "narration": "Разбойники окружили вас, и первый клинок ударил о щит.",
  "summary": "Герой сражается с разбойниками.",
  "requires_exertion": true,
  "health_delta": 0,
  "stamina_delta": -10,
  "music_mood": "battle"
}
```

Список разрешённых значений задаёт `Storytelling::MusicMood`. Неизвестное или отсутствующее настроение не отменяет корректный сюжетный ответ: сохраняется прежнее допустимое настроение, для нового прохождения это `calm`. Невозможное действие не переключает атмосферу. Семантический выбор настроения делает модель; сервер проверяет допустимость значения, а не ищет слова в команде.

`GameSession.music_mood` и `music_mood_changed_at` хранят состояние прохождения в SQLite. `PlayerAction.complete!` применяет настроение в той же транзакции, что рассказ, память, HP/STA. Откат, повтор задачи и восстановление после сбоя не создают повторного музыкального события. Состояния разных пользователей изолированы существующим приватным каналом.

Первая HTML-страница содержит атрибуты `data-music-*`. При последующих ходах те же атрибуты приходят с существующим Turbo Stream. После проверки версии и отрисовки `live_game.js` передаёт их в `RpiMusic.setScene`. Резервная сверка состояния и переподключение используют тот же путь. `localStorage` хранит только предпочтения громкости/включения, а не сюжетную атмосферу.

## Шесть оригинальных партитур

| Тема | BPM | Длина аранжировки | Синтез |
|---|---:|---:|---|
| calm | 72 | ≈107 с, 32 такта | Синусоидальные аккорды, бас, плавная мелодия в до мажоре |
| battle | 144 | ≈53 с, 32 такта | Короткие square/sawtooth-ноты, ре минор, синтезированные kick/snare/hat |
| tension | 54 | ≈142 с, 32 такта | Низкие triangle-пульсации, диссонансные кластеры и паузы |
| mystery | 78 | ≈98 с, 32 такта | Синусоидальные колокольчики с дополнительной частичной, расширенные аккорды, delay |
| sad | 58 | ≈132 с, 32 такта | Приглушённый triangle, ля минор, протяжённая мелодия с паузами |
| victory | 120 | 16 с, 8 тактов | Мажорная фанфара, яркий фильтрованный sawtooth, маршевые ударные |

В `soundtracks` записаны MIDI-высоты, аккорды, мелодические фразы, доли, длительности, тембры и фильтры. `compose` разворачивает их в события: четыре восьмитактовых раздела фона отличаются регистром, плотностью и ответными арпеджио. Мотивы повторяются с вариациями; это не бесконечная генерация новой композиции. Переход на начало следующего цикла сохраняет временную сетку, хвосты нот и delay не обрываются. Все данные и синтез оригинальные, CC0-1.0; внешние записи и библиотеки не используются.

Движок планирует короткое окно вперёд: таймер 25 мс, горизонт 180 мс; точное начало и окончание нот задаются по `AudioContext.currentTime`. У каждой ноты есть огибающая и фильтр; источники останавливаются и отключаются после окончания. Ударные используют синусоидальный частотный спад и шум, вычисленный в памяти браузера, а не загруженный сэмпл. Общий gain и компрессор сохраняют запас по громкости.

## Переключения, победа и настройки

Один живой `AudioContext` обслуживает все темы страницы. Темы идут через отдельные gain-шины: старый gain уменьшается с 1 до 0, новый увеличивается с 0 до 1 за 2,5 секунды. После перехода старые источники и граф отключаются. Максимум — две темы одновременно. Если за время перехода пришло несколько настроений, хранится только последнее желаемое: после завершения текущего crossfade начинается переход к нему. Одинаковое настроение не перезапускает аранжировку. Новая сессия сбрасывает партитуру даже при прежнем настроении.

`victory` звучит один раз и возвращается к `calm`. Время начала хранится на сервере отдельно от `updated_at`, поэтому pending-запросы и повторные снимки не продлевают фанфару. При перезагрузке в её пределах воспроизводится оставшаяся часть; после 16 секунд сервер и клиент считают фоном `calm`. Новая значимая победа после окончания может запустить новую фанфару. Повторный `victory` внутри текущих 16 секунд не перезапускает её.

Громкость 0–100% и включение сохраняются прежним `RpiPreferences`. В выключенном состоянии сюжет меняет выбранную тему, но не запускает звук. После включения звучит актуальная тема. На странице настроек звук не создаётся: она только меняет предпочтения. Скрытая вкладка плавно глушится и приостанавливает контекст; при возврате продолжает его. Если браузер запрещает autoplay, нужен клик/клавиша на игровом экране. При уходе (`pagehide`) или завершении прохождения закрываются контекст, таймеры и источники; восстановление из BFCache создаёт контекст заново. Это создание после ухода, а не при переключении тем.

Текущая тема сообщается через существующий `[data-music-status]` (доступный скринридеру статус). Обязательного ручного выбора в интерфейсе нет.

## Запуск и демонстрация

```powershell
cd D:\RPI
ruby bin/rails db:migrate
ruby bin/rails server
```

Для production-демонстрации перезапустите `script/share.ps1`: он выполняет `db:prepare` и сборку assets. Платный ключ требуется только рассказчику. Без API музыка гостевого режима остаётся спокойной. Сама музыка не обращается в сеть.

Для проверки тем без платных сюжетных запросов откройте игру и выполните в консоли браузера:

```javascript
// Локальный preview; БД и настройки включения не изменяются.
const game = document.querySelector('[data-game]');
RpiMusic.setScene({
  musicGameId: game.dataset.musicGameId,
  musicMood: 'battle', // calm, battle, tension, mystery, sad, victory
  musicChangedAt: new Date().toISOString()
});
RpiMusic.inspect(); // число контекстов, тем, активных источников и состояние
```

Следующий сюжетный снимок может вернуть серверную атмосферу — preview не сохраняется. `RpiMusic.renderPreview('mystery', 4)` возвращает Promise с `AudioBuffer`, вычисленным настоящим `OfflineAudioContext`. Это QA-инструмент без воспроизведения/экспорта файлов; он не создаёт дополнительные живые контексты и не участвует в обычной игре.

## Проверки

```powershell
node --test test/javascript/music_test.cjs
ruby bin/rails test
ruby bin/rails test:system --seed 17092
ruby bin/rails test:system --seed 24502
# Дополнительная проверка установленного Microsoft Edge:
$env:RPI_MUSIC_BROWSER='edge'
ruby bin/rails test:system --include /AdaptiveMusicTest/
Remove-Item Env:RPI_MUSIC_BROWSER
```

Серверные и браузерные наборы запускаются последовательно из-за общей тестовой SQLite. Тесты не используют настоящий API-ключ и платные вызовы.

- Ruby: контракт всех шести настроений, безопасный fallback, прежний mood во входе модели, сохранение/перезагрузка, повторные результаты, rollback, восстановление прерванного хода, ограниченное время victory, новая игра и изоляция пользователей.
- Node: темпы и непустые разные партитуры, планирование нот, одинаковое настроение, длительность crossfade, очередь быстрых изменений (не более двух тем), громкость всех тем/выключение/0%, autoplay, видимость, pagehide/BFCache, ограниченность ресурсов, полный цикл каждого фона, неизвестные значения и неподдерживаемый браузер.
- Реальный браузер: все шесть тем рендерятся Web Audio в разные конечные ненулевые сигналы с пиком ниже 0,98; сюжет меняет тему, повтор не перезапускает, reload восстанавливает её, выключение и громкость сохраняются, уход закрывает узлы. Исходные игровые system tests остаются в общем прогоне.

В тестовой инфраструктуре есть узкая совместимость с Chromium 158: Capybara 3.40 передаёт `origin="*"` при очистке хранилища, а новые Chrome/Edge отвергают его. В тестах вместо `*` используется фактический origin тестового приложения; очистка cookie/настроек сохраняется. Код приложения и пользовательские браузерные настройки это не меняет.

Проверено 25 ноября 2026 года:

- `rails test`: 191 тест, 2479 проверок, без ошибок и пропусков.
- Node: 8 тестов, все прошли.
- Chrome 158.0.8127.88: весь system-набор, по 11 тестов и 134 проверки с seed 17092 и 24502, без ошибок и пропусков.
- Microsoft Edge 158.0.4370.33: 4 музыкальных system-теста, 64 проверки, без ошибок и пропусков.
- RuboCop: 92 Ruby-файла, нарушений нет.
- Ручная проверка гостевого интерфейса: запуск после клика, переход в настройки, изменение громкости, выключение, возврат в игру и повторное включение. Интеграция DeepSeek проверялась заглушками транспорта; платных запросов при проверке не было.

Браузерные тесты измеряют реальные аудиобуферы и управление движком, но не заменяют субъективную оценку мелодий на слух. Safari и Firefox в этой среде не проверялись.
