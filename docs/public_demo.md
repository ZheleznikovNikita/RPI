# Публичная демонстрация с домашнего ПК

Аренда сервера и Docker не нужны. ПК запускает Rails, а SSH-туннель даёт временную публичную HTTPS-ссылку. Телефону или другому ПК достаточно браузера, находиться в одной Wi-Fi сети не требуется.

## Запуск на Windows

Все приведённые относительные команды вводятся **в корневой папке проекта**, где лежат `Gemfile`, `README.md` и папки `bin`, `script`. На текущем ПК в каждом из двух окон сначала выполните:

```powershell
cd D:\RPI
```

На другом ПК замените этот путь на путь его копии проекта. Сам скрипт определяет корень по своему расположению, поэтому его также можно вызывать по абсолютному пути.

Нужны установленные Ruby/Bundler проекта и OpenSSH (`ssh -V`). В каталоге проекта сначала выполните `bundle install`, если зависимости ещё не установлены.

В первом PowerShell:

```powershell
.\script\share.ps1
```

Скрипт готовит production-базу и assets, запускает Rails только на `127.0.0.1:3002`. Дождитесь `Listening`. Во втором PowerShell из каталога проекта:

```powershell
.\script\share.ps1 -Mode tunnel
```

Скопируйте именно HTTPS-ссылку, напечатанную localhost.run. Откройте её на другом устройстве, желательно также проверить через мобильный интернет. Зарегистрируйте демонстрационный аккаунт: аккаунты из development-базы здесь отсутствуют.

Если localhost.run недоступен, остановите второй процесс и попробуйте:

```powershell
.\script\share.ps1 -Mode tunnel -Provider pinggy
```

## Сколько действует ссылка и где найти новую

У бесплатного localhost.run нет обещанного фиксированного срока жизни URL: адрес периодически меняется, даже при работающем соединении. Перезапуск SSH также может дать другой адрес. Доступ требует непрерывной работы ПК, Rails и туннеля; выключение, сон или обрыв соединения могут прекратить его раньше. Бесплатная сессия Pinggy ограничена 60 минутами; после переподключения адрес может измениться.

Текущий адрес печатается во **втором окне PowerShell**, где выполняется `-Mode tunnel`; при ротации смотрите новые сообщения этого окна. Markdown и GitHub автоматически не обновляются. Ссылку, выданную при тестировании, намеренно не фиксируем в репозитории как постоянную.

Если доступа к ПК нет, текущая реализация **не позволяет удалённо узнать новую ссылку**. Сохранённая на телефоне старая ссылка не перенаправляет на новую. Попросите человека у ПК прислать адрес либо заранее настройте отдельный удалённый доступ/защищённую доставку ссылки. Автоотправка уведомлений сейчас не реализована. Для постоянного адреса потребуется сервис с закреплённым доменом; бесплатный случайный URL не даёт такого обещания.

Публиковать в GitHub нужно код и эту инструкцию, но не базы, session secret, `.env`, логи или файлы из `tmp`. Они исключены `.gitignore`. Не добавляйте их принудительно через `git add -f`. Публичность исходников сама по себе не предоставляет доступ к локальным файлам или к управлению туннелем; при этом сайт по публичной ссылке остаётся доступен посторонним, а безопасность приложения требует самостоятельных проверок.

При запросе пароля Pinggy нажмите Enter. Возможна промежуточная страница сервиса перед входом на сайт. Бесплатный Pinggy имеет ограничения времени сессии; новая сессия может получить новый адрес. localhost.run также меняет бесплатные адреса и ограничивает скорость. Скрипт не обещает постоянного домена и не перезапускает туннель бесконечно.

Если PowerShell запрещает запуск локального скрипта, можно запустить его отдельным процессом без изменения постоянной политики системы:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\script\share.ps1 -Mode server
powershell -NoProfile -ExecutionPolicy Bypass -File .\script\share.ps1 -Mode tunnel
```

Порт можно задать через `-Port 3010` в обоих окнах. Не направляйте туннель на старый development-сервер.

## Что хранится и кто имеет доступ

- Это production-режим без подробных страниц ошибок и web-console. При `RPI_PUBLIC_TUNNEL=1` включены HTTPS, secure cookies и ограничение Host доменами двух сервисов. Этот флаг следует использовать только за доверенным HTTPS-туннелем.
- Данные сохраняются в `storage/production*.sqlite3`, ключ cookie-сессий — в `storage/share-secret-key`. Эти файлы игнорируются Git. Не публикуйте их и резервируйте отдельно. Скрипт не копирует и не удаляет development-базу.
- Ссылка публичная: доступ есть у любого, кто её получил. Туннель не добавляет отдельную авторизацию ко всему сайту; приватные данные защищает существующая авторизация Rails. Это режим временного показа, а не проведённый аудит готовности к постоянному публичному размещению.
- HTTPS завершается у оператора туннеля: он является посредником трафика. Не используйте реальные персональные данные для демонстрации.
- Проброс портов на роутере и изменение брандмауэра не требуются. ПК, Rails и SSH должны работать, спящий режим прерывает доступ.

Для остановки нажмите Ctrl+C во втором окне (туннель), затем в первом (Rails). Данные останутся. При смене домена нужно снова войти, так как cookie относятся к прежнему адресу.

После остановки демонстрации перед работой над CSS/JS в development можно выполнить `ruby bin/rails assets:clobber`: это удалит скомпилированные assets, чтобы браузер не получал старую сборку. Перед следующим публичным запуском скрипт соберёт их снова.

## Диагностика

1. `http://127.0.0.1:3002/up` на ПК должен отвечать успешно. Если нет — проверьте первое окно.
2. Если SSH не подключается, смотрите ошибку второго окна и переключите провайдера. Порт 443 у Pinggy не означает, что SSH становится HTTPS: некоторые сети могут блокировать его отдельно.
3. Если HTTPS-ссылка открывается на ПК, но не на телефоне, проверьте другую сеть и второй сервис. Это ограничение маршрута/провайдера; не гарантия ошибки Rails.
4. Если Rails пишет `Blocked hosts`, сохраните имя домена. Не отключайте защиту через `config.hosts.clear`: сервис мог поменять домены, и список нужно уточнить.

Доступность из РФ зависит от конкретной сети и текущих ограничений. Наличие двух сервисов даёт запасной вариант, но не гарантирует доступ при всех блокировках.

Документация: [localhost.run](https://localhost.run/docs), [его бесплатный режим](https://localhost.run/docs/forever-free), [Pinggy](https://pinggy.io/docs/).

## Проверка реализации

12.11.2026: скрипт запущен через Windows PowerShell, production-база подготовлена, assets собраны. localhost.run выдал HTTPS-домен; внешние GET главной страницы и CSS вернули 200, отправка гостевой команды с production cookie и CSRF-токеном вернула 200/completed. Запрос с посторонним Host получил 403. Общий набор: 152 теста, 2020 проверок, без ошибок. RuboCop для изменённой конфигурации проходит. Pinggy предусмотрен как резерв, но его доступность из внешней сети отдельно не подтверждена. Доступ с телефона через мобильную сеть должен проверить владелец устройства.
